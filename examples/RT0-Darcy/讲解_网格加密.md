## 1. 先看结论

把 4×4 的基准网格连续加密 3 次，误差这样下降（算例 2：$p=\sin\pi x\sin\pi y$）：

| 加密次数 $k$ | $h$ | 单元数 | 棱数 | 未知量 | $\lVert q_h-q\rVert$ | $\lVert p_h-p\rVert$ |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | 1/4 | 32 | 56 | 88 | $5.019\times10^{-1}$ | $2.686\times10^{-2}$ |
| 1 | 1/8 | 128 | 208 | 336 | $2.516\times10^{-1}$ | $6.950\times10^{-3}$ |
| 2 | 1/16 | 512 | 800 | 1312 | $1.259\times10^{-1}$ | $1.751\times10^{-3}$ |
| 3 | 1/32 | 2048 | 3136 | 5184 | $6.295\times10^{-2}$ | $4.387\times10^{-4}$ |

相邻两层的收敛阶：

| 层 | $q$ 的阶 | $p$ 的阶 |
| --- | --- | --- |
| 0 → 1 | 0.996 | 1.950 |
| 1 → 2 | 0.999 | 1.989 |
| 2 → 3 | 1.000 | 1.997 |

**读法**：$h$ 每减半，通量误差也减半（一阶），压力误差减到 1/4（二阶）。
"加密有效"的判据就是**阶稳定**（不要求是整数，0.95~1.05 算一阶）。

## 2. "加密"到底有哪几种

| 方式 | 做法 | 误差下降 | 备注 |
| --- | --- | --- | --- |
| **h 加密**（h-refinement） | 把三角形切小，$h\to h/2$ | $O(h^p)$ | 最常用，本文讲这个 |
| **p 加密**（p-refinement） | 不切小，提高单元上的多项式次数（RT0→RT1） | 指数（光滑解） | 需要更高阶的元和更高的求积 |
| **自适应加密**（adaptive） | 只在误差大的地方切小 | 同等自由度下更优 | 需要"误差指示子"（见第 6 节） |

## 3. 一致加密的两种写法

### 3.1 写法一：直接重新生成更细的网格

最省事：`make_rect_mesh(4, 4)` → `make_rect_mesh(8, 8)` → `make_rect_mesh(16, 16)`。

```python
for n in (4, 8, 16, 32):
    nodes, cells = make_rect_mesh(n, n)     # h = 1/n
```

缺点：
* 只能用于"规则区域 + 规则网格"；
* 每一步都要重新生成整张网格，**新旧网格没有对应关系**（不能做"把上一步的解搬到新网格上当初值"）；
* 遇到复杂区域（L 形、圆、多孔介质）就写不出 `make_rect_mesh` 了。

### 3.2 写法二：把已有网格"一分为四"（red refinement）★

这是有限元里最标准的做法，适用于**任何**三角形网格：

1. 取每个三角形三条边的**中点**；
2. 把原三角形和三个中点连起来，得到 4 个全等的小三角形。

```
        c
        |\
        | \
       ca   bc          4 个小三角形：
        |    \             (a,  ab, ca)   左下
        |_____\            (ab, b,  bc)   右下
        a  ab  b           (ca, bc, c)    顶
                           (ab, bc, ca)   中间（倒过来）
```

代码就是 `refine_uniform(nodes, cells)`（在脚本第 2 部分），核心只有十几行：

```python
def edge_midpoint(i, j):
    key = (i, j) if i < j else (j, i)      # 排序，让 (3,7) 和 (7,3) 是同一个键
    if key in mid_of_edge:                  # 已经建过 → 复用
        return mid_of_edge[key]
    new_id = len(new_nodes)                 # 新建一个节点
    new_nodes.append([(x_i+x_j)/2, (y_i+y_j)/2])
    mid_of_edge[key] = new_id
    return new_id
```

**唯一容易踩的坑**：相邻两个三角形共享一条边，这条边的中点**只能建一次**。
所以要用字典 `mid_of_edge` 记住"这条边已经有中点了，编号是几"。
如果每个三角形各自建中点，就会得到一批"坐标相同但编号不同"的节点，
网格在拓扑上就**裂开**了（相邻单元不再共享边，RT0 的法向连续性也就无从谈起）。

### 3.3 加密一次，规模怎么变

| 量 | 加密前 | 加密后 | 原因 |
| --- | --- | --- | --- |
| 单元数 $M$ | $M$ | $4M$ | 每个三角形变 4 个 |
| 节点数 $N$ | $N$ | $\approx 4N$ | 边中点数量与被替代的边相当（精确值 $N+E$，其中 $E$ 是棱数） |
| 棱数 $E$ | $E$ | $2E + 3M$ | 每条旧棱变 2 段，每个三角形内部多 3 段 |
| 单元直径 $h$ | $h$ | $h/2$ | 中点连线把边长平分 |
| RT0 未知量 | $E+M$ | $2E+3M+4M$ | 棱自由度 + 单元自由度 |

脚本实测（基准 4×4，即 32 个单元）：

| 加密次数 | 单元数 | 倍数 |
| --- | --- | --- |
| 0 | 32 | 1 |
| 1 | 128 | ×4 |
| 2 | 512 | ×16 |
| 3 | 2048 | ×64 |

一眼就能看出：**每加密一次，单元数正好 ×4**。
原因很简单：$h$ 减半，单元面积按 $h^2$ 缩小，所以同一块区域要装 4 倍的单元。

## 4. 代码里加密是怎么"被用起来"的

```python
# 基准网格
nodes, cells = make_rect_mesh(4, 4)

# 加密 level 次（level = 0,1,2,3）
for level in range(4):
    nodes, cells = make_rect_mesh(4, 4)          # 每次都从基准开始，避免累积
    nodes, cells = refine_times(nodes, cells, level)
    h = 1.0 / (4 * 2**level)                     # ★ h 的公式
    ...组装、求解、算误差...
```

`h` 的公式值得记住：

$$h_k=\frac{h_0}{2^k}=\frac{1}{n_0\,2^k},$$

所以"加密 $k$ 次"等价于"$n$ 变成 $n_0 2^k$"。
脚本里 `h = 1.0 / (base_n * (2 ** level))` 就是这个式子。

## 5. 误差怎么随 h 下降：收敛阶的算法

设第 $k$ 层的网格尺寸 $h_k$、误差 $e_k$。由 $e\approx C h^{\alpha}$ 得

$$\alpha=\frac{\log(e_{k-1}/e_k)}{\log(h_{k-1}/h_k)}.$$

因为这里 $h_{k-1}/h_k=2$，公式退化成

$$\alpha=\log_2\frac{e_{k-1}}{e_k}.$$

代码就是这两行：

```python
rate_q = math.log(e1["err_q"] / e2["err_q"]) / math.log(e1["h"] / e2["h"])
rate_p = math.log(e1["err_p"] / e2["err_p"]) / math.log(e1["h"] / e2["h"])
```

实测 $q$ 的阶是 0.996、0.999、1.000 —— 说明代码、边界条件、求积都是对的。

### 为什么压力看起来是二阶？

因为比较方式：$p_h$ 是分片常数，我们拿它和**单元重心处**的精确值比。
三角形的重心恰好是"二阶精确"的中点公式点，所以

$$\bar p_K - p(x_K)=O(h^2),$$

也就是 P0 对光滑函数的"单元平均值"本身就有二阶精度，这部分误差不占主导。
RT0×P0 的**理论保证**是 $q$ 和 $p$ 都至少 $O(h)$，实测 $p$ 更好不矛盾。
写论文/报告时建议：

* 报"$q$ 一阶、$p$ 一阶（理论）"，并注明"实测 $p$ 达二阶，因重心点超收敛"；
* 或者干脆改用 $\lVert p_h-\bar p\rVert/\lVert \bar p\rVert$ 这类扣除平均值误差的量。

## 6. 自适应加密：只切"需要切"的地方

一致加密的问题是**浪费**：远离奇点/边界层的地方也被切细了。
自适应加密的流程是"**估计 → 标记 → 加密 → 重解**"循环：

```
solve → 每个单元算一个误差指示子 η_K → 标记 η_K 大的那些单元
      → 只加密被标记的单元 → 重新求解 → 重复
```

### 6.1 指示子怎么算

最常用的是**残差型指示子**（这里 $f_h$ 是 $f$ 的 $L^2$ 投影）：

$$\eta_K^2=h_K^2\lVert f-f_h\rVert_{L^2(K)}^2+\tfrac12\sum_{f\subset\partial K}h_f\lVert \lbrack\!\lbrack q_h\cdot n\rbrack\!\rbrack\rVert^2_{L^2(f)}.$$

（RT0 的法向通量跨单元连续，所以第二项通常为 0；对 P0 压力则要看
"$q_h$ 与 $-K\nabla p_h$ 的差"这类量。）

### 6.2 标记策略

* **最大值法**：标记 $\eta_K>\theta\max_K\eta_K$ 的单元（$\theta\approx0.5$）；
* **Dorfler 法**：把 $\eta_K$ 从大到小排序，取到累计平方和占 $\theta$（如 0.5）为止。

### 6.3 只加密一部分单元会带来"悬点"

相邻单元没被加密，就会出现"一条边的一半属于小三角形、另一半属于大三角形"
（**悬点 / hanging node**）。这时有两个选择：

1. **闭包（closure）**：把与标记单元共享边的邻居也加密，直到没有悬点
   （红绿加密：标记的做 red，邻居做 green）；
2. **允许悬点**：用**二分法**（bisection）加密——每次只把一条边平分，
   三角形一分为二，天然不产生悬点，适合做自适应。这也是
   `p4est`、`ALBERTA` 等自适应库的做法。

本脚本只实现**一致加密**（所有单元都切），因此不会出现悬点，逻辑最简单。

### 6.4 一个最小自适应循环（伪代码）

```python
for it in range(max_iter):
    Q, P = solve(nodes, cells)                 # 求解
    eta = [indicator(c) for c in range(len(cells))]   # 每个单元的指示子
    marked = [c for c in range(len(cells)) if eta[c] > 0.5*max(eta)]
    if len(marked) == 0: break
    nodes, cells = refine_marked(nodes, cells, marked)  # 只切标记的（需处理悬点）
```

## 7. 加密时的工程注意事项

| 项目 | 现象 | 应对 |
| --- | --- | --- |
| 自由度 | 每层 ×4（2D）/ ×8（3D） | 别盲目加 3 层以上；先看误差够不够 |
| 条件数 | 鞍点系统 $\kappa\sim h^{-2}$ 甚至更差 | 大网格改用稀疏 LU（`scipy.sparse`）或 MINRES + 预条件 |
| 内存 | 稠密矩阵 $O(N^2)$ | 脚本里"有 scipy 就用稀疏，没有就用稠密"（后者建议 $nx\le16$） |
| 组装耗时 | 显式循环是 $O(M)$，但 Python 慢 | 教学版保持循环；生产版向量化或用 C/Fortran |
| 边界节点 | 加密后新中点可能"跑出"边界 | 直线边界上中点仍在边界上；曲边界要投影回真实边界（否则几何误差变一阶） |
| 收敛阶退化 | 阶从 1 掉到 0.5 | 通常是指示子/边界处理/求积精度不够，或解有奇点（角点） |

## 8. 一个真实的 bug：Dirichlet 右端不能乘棱长

写这份代码时踩过一个坑，很适合当"检查清单"：

混合形式里压力 Dirichlet 项是

$$-\langle g_D,\ \boldsymbol v\cdot\boldsymbol n\rangle_{\Gamma_D}.$$

取检验函数 $\boldsymbol v=\boldsymbol\varphi_e$（面 $e$ 的 RT0 基函数），因为
$\int_e\boldsymbol\varphi_e\cdot\boldsymbol n\,ds=1$，所以这一项**正好等于** $-g_D$（棱中点取值），
**不该再乘棱长 $|e|$**。

我第一次写成了 `rhs -= g * length`，结果：

* 算例 1（均匀流）的 $\boldsymbol q_h$ 变成 $(0.3125,0)$，而正确值是 $(2.5,0)$ —— 差了 $1/h=8$ 倍；
* 简单验证：把精确解插到自由度上，检查 $A\Phi-B^{\mathsf T}P=b$ 的残差，最大残差恰好 $=g\cdot|e|$；
* 修正后：$\lVert q_h-q\rVert=1.07\times10^{-15}$，$\boldsymbol q_h=(2.5,0)$，逐单元散度 $5.6\times10^{-16}$。

**教训**：RT0 的基函数是"通量归一化"的（$\int_e\varphi\cdot n=1$），所以凡是
"对边界的积分"都要先想清楚**归一化带来的是 1 还是 $|e|$**。
修完之后建议固定加两条自检：

1. 把精确解插值到自由度，检查线性系统残差（应为机器零）；
2. 有精确解时检查 $\lVert q_h-q\rVert$（应为机器零，而不是"小"）。

## 10. 一句话总结

**加密 = 把 $h$ 变小；一致加密最稳的写法是"一分为四 + 中点去重"；
加密有没有用，看误差的收敛阶稳不稳；只切该切的地方就是自适应，
代价是要处理悬点（闭包或二分法）。**
